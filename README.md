# AstrBot 上下文哨兵

**版本：0.2.0** · 轻量级、只读的上下文用量监控插件

上下文哨兵定期读取 AstrBot 的 `data_v4.db`，监测你指定的私聊和群聊会话的 `token_usage`。达到配置的用量阈值后，向你绑定的私聊和群聊发送提醒。

> 本插件只负责读取、监测和提醒。它不会调用模型，不会自动整理日记或笔记，也不会修改聊天记录或 AstrBot 主数据库。

## 功能

- 通过 AstrBot 提供的 `get_astrbot_data_path()` 定位数据目录，不把 `/root/AstrBot` 等特定设备路径写死。
- SQLite 以 `mode=ro` 只读方式打开，并启用 `PRAGMA query_only=ON`；不对 `data_v4.db` 执行写操作。
- 自动查找包含 `user_id` 和 `token_usage` 的数据表；必要时允许手动指定表名。
- 支持分别配置一个私聊和一个群聊数据库 `user_id`。
- 达到阈值时向绑定的通知会话发送提醒，并持久化通知状态，降低重复提醒和重启后状态丢失的风险。
- 可选按更新时间过滤陈旧数据。

## 安装

1. 下载本项目 ZIP。
2. 在 AstrBot WebUI 打开「插件」页面，选择从本地文件安装/上传插件 ZIP。
3. 安装后启用插件；如果插件未自动加载，在插件页面重载一次。
4. 打开插件配置页面，先设置下文的监控会话 ID 和上下文窗口。

无需额外安装 Python 第三方依赖；插件使用 Python 标准库 `sqlite3`、`asyncio` 等，以及 AstrBot 自身 API。

## 首次配置

### 1. 找到要监控的数据库会话 ID

在 AstrBot 管理员私聊中发送：

```text
/记忆监控 会话列表
```

插件会读取数据库中候选会话，显示 `user_id`、`token_usage` 和可用的更新时间。请在**管理员私聊**中查看，列表可能包含你的其他会话标识，不建议把结果发到公开群聊。

如果自动识别到多个数据表而无法确定目标，请先在插件配置 `table_name` 中填写正确表名（例如 `conversations`），再执行会话列表。

### 2. 填写监控会话 ID

在插件配置中设置：

| 配置项 | 含义 |
|---|---|
| `friend_user_id` | 要监控的私聊数据库 `user_id` |
| `group_user_id` | 要监控的群聊数据库 `user_id` |
| `table_name` | 数据表名；通常可留空自动识别 |
| `context_window_tokens` | 当前模型的上下文窗口上限（tokens） |
| `threshold_percent` | 预警比例，默认 80% |
| `reset_percent` | 重新武装比例，默认 75% |
| `poll_interval_seconds` | 轮询间隔，默认 60 秒 |

`context_window_tokens` 必须按你实际使用的模型填写。默认的 1,000,000 只是示例值，不代表所有模型都具有 100 万上下文窗口。预警触发值 = 上下文窗口 × 预警百分比。

### 3. 绑定接收提醒的会话

在希望接收私聊提醒的私聊窗口发送：

```text
/记忆监控 绑定私聊
```

在希望接收群提醒的目标群发送：

```text
/记忆监控 绑定群聊
```

绑定命令要求管理员权限，且必须在对应类型的会话中执行。绑定结果保存在插件自己的状态文件中。

### 4. 检查并测试

```text
/记忆监控 检查
/记忆监控 测试
```

`检查` 会显示数据库路径、识别到的数据表、更新时间列、私聊/群聊用量、数据年龄和绑定状态。`测试` 会向已绑定的通知目标发送测试消息。

## 更新时间与数据新鲜度：请先理解这一点

不同 AstrBot 版本或数据库结构中，`updated_at` 的含义可能不同。它**不一定会在 `token_usage` 每次变化时同步更新**。如果直接把它作为新鲜度依据，可能把仍然有用的 token 数值误判为陈旧数据，从而不发送提醒。

因此，本插件 0.2.0 默认：

- `freshness_enabled = false`：不使用更新时间拦截阈值判断；仍会读取并显示识别到的更新时间。
- `freshness_seconds = 600`：只有开启更新时间过滤时才生效，600 秒等于 10 分钟。

只有在你确认某个更新时间字段会随 `token_usage` 同步刷新后，才建议：

1. 将 `updated_at_column` 设置为真实字段名（常见名称为 `updated_at`，但请以实际数据库为准）。
2. 开启 `freshness_enabled`。
3. 按数据库真实刷新周期设置 `freshness_seconds`。

如果尚未确认更新时间字段的语义，请保持过滤关闭，并留意 `token_usage` 本身是否按预期刷新。关闭过滤并不保证数据库中的旧用量一定仍准确；这需要结合实际 AstrBot 行为观察。

## 命令一览

| 命令 | 作用 | 权限/位置 |
|---|---|---|
| `/记忆监控 状态` | 查看当前配置和最近一次读取结果 | 普通用户可用 |
| `/记忆监控 检查` | 立即只读检查数据库 | 普通用户可用 |
| `/记忆监控 会话列表` | 列出数据库中的候选 `user_id` | 管理员；建议在私聊使用 |
| `/记忆监控 绑定私聊` | 将当前私聊绑定为通知目标 | 管理员；必须在私聊使用 |
| `/记忆监控 绑定群聊` | 将当前群绑定为通知目标 | 管理员；必须在群聊使用 |
| `/记忆监控 测试` | 向已绑定目标发送测试消息 | 管理员 |

也可以使用命令别名 `/ctxguard`。

## 触发规则

- 当某个已配置会话的 `token_usage` 达到或超过预警值时，向已绑定的目标发送通知。
- 同一会话首次触发后不重复刷屏；当用量降到 `reset_percent` 或以下时重新武装。
- 私聊和群聊分别记录触发状态。
- 如果目标消息发送失败，只会在后续轮询中继续尝试未成功的目标。
- 插件状态保存在 AstrBot 数据目录下的 `plugin_data/astrbot_plugin_context_guard/state.json`，不写入 `data_v4.db`。

## 安全与隐私

- 本插件只读 `data_v4.db`；不执行 `INSERT`、`UPDATE`、`DELETE`、DDL 或手动 checkpoint。
- 使用 SQLite URI `mode=ro`，并设置 `query_only`。不使用 `immutable=1`，以免在 WAL 场景下忽略尚未合并的数据页。
- `会话列表` 会显示数据库中的会话 `user_id`，请仅在可信管理员私聊中执行，不要公开分享完整输出。
- 插件不读取或上传聊天正文，不向外部服务器发送数据。
- 插件不会自动整理或备份日记、笔记、聊天原文；重要数据仍应定期备份。

## 常见问题

**检查时显示“未配置数据库 user_id”**  
先在管理员私聊执行 `/记忆监控 会话列表`，然后把对应 ID 填入 `friend_user_id` 或 `group_user_id`，保存配置并重载插件。

**没有找到数据表，或提示多个表无法确定**  
检查数据库中是否存在包含 `user_id` 和 `token_usage` 的表；若有多个候选，在 `table_name` 中填写正确表名。

**显示用量，但一直没有预警**  
确认对应 `user_id` 已配置、用量确实达到阈值、插件启用且至少绑定一个通知目标。若启用了新鲜度过滤，先检查时间列是否真的随 `token_usage` 更新；未经验证时建议关闭 `freshness_enabled`。

**测试消息发送失败**  
确认机器人在绑定的私聊/群中在线、当前平台适配器正常，并重新执行相应绑定命令。

**升级或卸载会丢失状态吗？**  
状态文件在 AstrBot 的 `data/plugin_data/astrbot_plugin_context_guard/`，正常更新插件时不应删除此目录。卸载前如需保留绑定和提醒状态，请先备份该目录。

## 兼容性与测试说明

本插件在一个 AstrBot 泡泡版环境中完成过 SQLite 只读检查及 QQ 通知投递测试。不同 AstrBot 核心版本、平台适配器、数据库表结构仍可能存在差异；首次启用后请执行 `检查` 和 `测试`，确认实际环境可用。

本项目不承诺监测值与模型真实上下文窗口完全一致。请根据模型提供商、AstrBot 上下文配置和实际压缩行为设置窗口及阈值。
